# Domain documentation

Layout: **single-context**.

- Read `CONTEXT.md` before planning or implementing changes.
- Store durable architectural decisions under `docs/adr/`.
- Use the glossary in `CONTEXT.md` in code, tests, issues, and documentation.
- Update `CONTEXT.md` when a new core concept is introduced or an existing term changes meaning.
- Add an ADR when a decision changes system boundaries, security posture, data provenance, execution authority, or deployment architecture.

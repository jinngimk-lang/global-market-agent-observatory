# Trading Ecosystem Watch — 2026-08-25

This note records externally verified developments that were reviewed for the autonomous trading platform. It is an evidence/provenance record, not an instruction to weaken runtime safety or promote strategies.

## Alpaca

### Verified developments

- 2026-08-05: Alpaca upgraded the Trading API OpenAPI description to OpenAPI 3.1.
- 2026-08-10: Alpaca's Trading MCP documentation access became available for API-reference retrieval.
- 2026-08-17: Alpaca migrated schema examples to standard OpenAPI 3.1 examples.
- Alpaca publishes current Trading, Market Data, Broker, and auth OpenAPI files from its official documentation site.

### Project relevance

The repository's Alpaca execution and account-observer boundary was checked against the currently documented Trading API surface used by the project: account, positions, orders, query-by-client-order-id, submit order, and cancel order. No production-code change is required from these documentation/schema changes alone.

The current order-status mapper already handles `accepted`, so the recently documented `accepted` trade-update state does not require a compatibility patch.

### Integration decision

- Do not vendor generated Alpaca clients merely because the OpenAPI format changed.
- Prefer official Alpaca OpenAPI/docs as the contract source when adding or changing Alpaca endpoints.
- Any future generated-client experiment must remain behind the existing execution/risk boundary and receive contract tests before replacing handwritten transport code.
- No secrets, account identifiers, or live-trading permissions are introduced by this review.

## Interactive Brokers

### Verified development

Interactive Brokers published TWS API Latest 10.49 on 2026-08-04. Stable remains 10.45 (2026-03-30). IBKR states that its API software is distributed under its own license and that market-data dissemination to third parties is restricted without prior approval.

### Project relevance and decision

- Treat API 10.49 as the current compatibility-reference baseline when evaluating future TWS API work.
- Do not vendor or copy IBKR API source into this repository without a dedicated license review.
- The current project should continue to isolate IBKR behind its broker adapter and deterministic reconciliation/risk boundaries.

## NautilusTrader

### Verified developments

NautilusTrader remains under active v2 development. Recent public work includes restart/order-identity recovery, subscription recovery, backtest custom-data injection, and cache-history introspection. Its documentation warns that APIs can still break before v2 stabilizes. The project is LGPL-3.0 licensed.

### Project relevance and decision

The restart/recovery and backtest/live-parity ideas remain useful references for our reconciliation, replay, and failure-injection work, but the current maturity and LGPL boundary argue against importing framework code into the trading core. Study patterns; implement independently unless a later, scoped integration passes license/security review.

Official sources reviewed:

- https://nautilustrader.io/open-source/
- https://nautilustrader.io/docs/latest/getting_started/installation/

No NautilusTrader source code was copied in this review.

## Security and supply-chain conclusion

This review deliberately avoids adding new runtime dependencies. That is the lowest-risk response to the current ecosystem changes: the useful changes are contract/documentation updates, not missing capabilities that justify adding package or binary supply-chain exposure.

Future external integrations must continue to pass:

1. source authenticity and recency check;
2. license compatibility and attribution review;
3. security/advisory and dependency review;
4. smallest-scope adaptation;
5. failing behavioral/contract test first where applicable;
6. full static/test/CI verification;
7. provenance record with upstream repository/tag/commit or official API source;
8. no automatic strategy promotion or live-capital enablement.
